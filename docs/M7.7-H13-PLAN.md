### B0 — THE PASS CLOCK AND THE CHAIN SPINE

**Scope.** `$8D0C-$8D70` as a **free-running loop with no frame wait**: the `$8D05` PUSH / `$8D11 RET`
pair that brackets an entire game, `$8D12`'s second round-advance driver `$FECD`, `$8D1E`'s per-PASS
counter `$FEC8` and its 256-wrap call to `$7FFC`, and the 21-call chain wired in the machine's order
(the `mainLoop()` stub list at web/game.js:4028, including the two routines that are transliterated
but NOT wired — `$8669` and `$C002`). Plus the **two frame counters as self-modified 16-bit
immediates** (`$8DB5`/`$8DB6-7`, `$8DBC`/`$8DBD-E`: each is a `LD HL,nn` whose operand is the storage,
+1 per **video frame**, measured 200/200), and the **three divider idioms as one shared
transliteration**: `$A82C` `CP n / LD (n),A` (A is the value READ -> an EDGE DETECTOR, 898 passes in
8,547 = 0.997/frame), `$A9FF` `SUB n / LD (n),A` (A is the DIFFERENCE -> an **INVOLUTION**, a 2-cycle
summing to T, 13 latches in 900 frames at **stride 2**), and `$AA05` `LD A,n / INC / AND $1F` (the only
real divider, over passes). A whole-image scan puts the CP form at 6 sites and the SUB form at
exactly one — `$A9FF` is the odd one in 64K, and all seven carry the cold immediate `$2A`.

**Oracle.** `tools/passclock.py` -> `build/passclock_fixture.json`. The world that makes this gate
able to fail is not a state at all, it is **two machines**: the SAME state run with
`Harness(contended=True)` and `contended=False`. A capture has one pass rate and therefore cannot
distinguish a pass counter from a frame counter. Rows: (a) boss.pkl 300 and 900 frames, both
contention settings, logging every `$A9ED` entry with `(SP)`, `$AA06`, `$AA00`, `$8DBD` — anchors
2890 vs 2933 passes, 90 vs 91 body fires, **PASS interval exactly 32 in every interval of both runs**
while the frame interval mean moves 3.324 -> 3.277 with a spread of 3.06..4.49. (b) the `$A9FC`
orbit **BUILT**: seed `$AA00 := mem[$8DBD]` and assert the very next call latches and then every
other call — zero latches in the first 300 frames of either shipped boss state, so a captured world
tests nothing. (c) `$FECD` poked 0/1/3, asserting `$8609` moves by exactly that many **fully built,
immediately discarded** rounds. (d) return-address verification for both call sites
(`$8D2E`->`$8D31` on 2890/2890, `$8D46`->`$8D49` on 2890/2890) — the H9 method, which is the only one
that survives a tail call.

**Negatives.** There is **no HALT and no frame wait** anywhere in `$8D0C..$8D70` — assert that the
engine's pass loop is bounded by the T budget and by nothing else. `$8DBD` advances **once per frame**
while `$FEC8` advances ~9.5x — assert both against each other in the same run, because a port that
ties them together passes every single-counter gate. `$7FFC` fires on `$FEC8`'s 8-bit wrap — 7 times
in 200 frames, **not** once per 256 frames.

**Equal answers.** *"The divider counts frames"* and *"the divider counts passes"* agree at
32/9.5 ≈ 3.33 on any single run — **the contention toggle separates them** and nothing else does.
*"CP writes back a constant"* and *"CP writes back the value it just read"* agree whenever the timer is
still — drive with the timer MOVING. *"SUB is a divider"* and *"SUB is an involution"* agree for 300
frames from either shipped boss state (0 latches) — seed the orbit to contain 0 and assert the
**stride-2** absorbing behaviour, which is the opposite of a divider. And a gate that merely checks
`$A9FC` "returns at `$AA05`" is satisfied by deleting the whole block.

**Risk.** **HIGH, and architectural.** Wiring the chain changes the pass rate, which re-baselines
every frame-count gate already in `test/bb.test.js`; and the pass rate is an emergent property of Z80
timing that a JS port reproduces only as well as docs/TIMING.md's cost model does. If the derived
rate cannot be brought inside the machine's own contention spread (3.06..4.49 frames per body fire),
**the cadence becomes a DECLARED DEPARTURE with a flag** and the faithful assertion retreats to the
PASS interval. Say which it is in the commit; do not let it be decided silently.

**AGENTS.** It attacks a belief (the port's flat `BB_PASS_T` and its stub chain), and two of its
inputs are open machine behaviour that nobody has measured: **who calls `$AA60`** (not one of the 20
CALLs in `$8D25..$8D5E`) and **why `$A98F/$A990` decrement at 0.5 per frame** while the loop runs
9.5x — the walker is itself gated and the gate is unfound. Both belong to the pass rate.

### B5 — THE OVERLAP TEST, `$A98F/$A990`, AND THE DAMAGE TAIL

**Scope.** `$A969` (P2 `$FD8A` FIRST, P1 `$FD80` second, IX returns holding the match), `$A97D` the

correct"* and *"the comparator was deleted"* are the same if `$A98F` holds `37 C9` — force `00 00` and
